# HIT 课程报告作业撰写

## 核心原则

**先有证据，再动笔。** 顺序不能颠倒：

```
读作业要求 → 拆评分点 → 检索几十篇真实文献 → 读摘要筛选 → 用户确认 → 下载原文 → 写作 → 去AI味 → 对账 → 排版
```

最容易被老师抓的两件事——**编造文献**和**AI 味太重**——都靠流程卡死，不靠自我提醒。

## 依赖

| 能力 | 来源 | 用途 |
|---|---|---|
| 文献检索下载 | `hit-cnki-refs` skill | 真实文献 + 原文文件 |
| 排版 | `hit-standard-word-type` skill | 字体字号、三线表、公式、参考文献格式 |
| 文档生成 | `workbuddy-docx` / `workbuddy-local-office-edit` | 输出 .docx |

开工前确认 `hit-cnki-refs` 的 `check` 能过。不能过就先解决环境，别用记忆里的文献凑数。

## 工作目录

每份作业独立目录，脚本靠固定结构定位文件：

```
<课程>-<作业名>/
├── 00-intake.md        作业要求原文 + 评分点拆解 + 章节字数分配
├── 01-outline.md       带论点的详细提纲
├── 02-shortlist.md     文献候选清单（hit-cnki-refs 生成，等用户确认）
├── 03-final.md         定稿（含 [@key] 引用标记）
├── 04-交付稿.md         渲染后（编号已重排、参考文献已生成）
├── refs/
│   ├── refs.json       唯一事实源：题录 + 状态 + 文件 + 校验
│   ├── 001-*.pdf       原文
│   └── 02-shortlist.md
└── 交付-<题目>.docx
```

## 七步流程

### 第 1 步 · 需求采集

读用户给的作业要求（文字/截图/PDF 都行），填 `references/intake.md` 的采集单，写到 `00-intake.md`。

必须问清这四项，缺一项就问，别猜：

1. **作业原文要求**（老师怎么说的，含字数、格式、提交方式）
2. **评分标准**（有 rubric 最好；没有就问"老师课上强调过什么"）
3. **课程名 / 任课教师 / 学院专业班级学号姓名**（封面要用）
4. **截止时间与是否查重**（查重会影响改写策略）

### 第 2 步 · 按评分点搭骨架

不要套模板，**从给分逻辑反推结构**。方法见 `references/rubric-mapping.md`。

作业类型骨架（章节 + 字数配比）见 `references/assignment-types.md`：

| 类型 | 典型字数 | 结构重心 |
|---|---|---|
| 实验报告 | 2000–5000 | 数据、误差分析、结论的可复现性 |
| 调研报告 | 3000–8000 | 调研方法、样本、数据支撑、对策 |
| 文献综述 | 3000–6000 | 脉络梳理、观点对比、研究空白 |
| 课程设计 | 5000–10000 | 方案论证、实现、测试、改进 |
| 读书报告 | 1500–3000 | 原书观点复述 + 个人批判 |
| 小论文 | 3000–6000 | 问题、论证、证据、反驳 |

产出 `01-outline.md`：每节写**论点句**（不是"介绍XX"，而是"XX 的主要原因有三，其中 YY 最关键"），并标注该节需要几篇文献支撑。

### 第 3 步 · 检索与泛读

按提纲每节生成检索词，交给 `hit-cnki-refs`：

```bash
python3 <hit-cnki-refs>/scripts/cnki.py search "词A 词B" "词C 词D" --limit 20
python3 <hit-cnki-refs>/scripts/cnki.py abstract --limit 40
```

**总量目标：综述/调研类 ≥30 篇，实验类 ≥10 篇，读书报告 ≥3 篇。** 读得少，写出来就是通识废话。

读完摘要，你要能回答：这个领域分几派、主流方法是什么、近两年在争什么、哪篇是绕不开的。

### 第 4 步 · 筛选 + 等用户确认（硬性闸门）

```bash
python3 <hit-cnki-refs>/scripts/cnki.py shortlist --n 30
```

基于 `02-shortlist.md`，给出**你的推荐清单**：每条写"用它支撑哪一节 + 一句话理由"。

然后**停下来问用户**（用 AskUserQuestion 或直接列清单让用户勾）。不要自己决定引用哪些，不要在确认前下载。

推荐数量：正文引用数 ≈ 总字数 ÷ 400，综述类可到 ÷ 250。

### 第 5 步 · 下载与校验

```bash
python3 <hit-cnki-refs>/scripts/cnki.py confirm --keys k1,k2,k3
python3 <hit-cnki-refs>/scripts/cnki.py download --prefer pdf
python3 <hit-cnki-refs>/scripts/cnki.py verify
```

`verify` 不过不许进入写作。下载失败按 `hit-cnki-refs` 的人工接管协议处理。

### 第 6 步 · 写作

**唯一允许的引用写法：`[@key]`**，key 来自 `refs.json`。禁止在正文里直接写 `[1]`，禁止自己写参考文献列表。

写的时候守三条：

- **边写边挂引用**。写完再补引用必然出现"这句话到底谁说的"的失忆，进而编造
- **引用要贴着具体主张**。`据文献[@k1]` 是废话，`XX 在 300℃ 以上会触发热失控[@k1]` 才是引用
- **没有文献支撑的判断要么删，要么明确标注为个人观点**（"笔者认为…"），不能让读者误以为是文献结论

去 AI 味的要求见 `references/anti-ai-style.md`，写作时就照着写，不要等写完再洗——洗出来的痕迹更重。

### 第 7 步 · 三审后交付

```bash
# 1. 引用对账（硬闸门，退出码非 0 不许交付）
python3 scripts/refs_audit.py check --draft 03-final.md --refs refs

# 2. 渲染参考文献并重排编号
python3 scripts/refs_audit.py render --draft 03-final.md --refs refs --out 04-交付稿.md

# 3. 去 AI 味检测
python3 scripts/style_lint.py 04-交付稿.md
```

`style_lint` 报 FAIL 就回去改，别只改被点名的句子——**改句式节奏，不是替换同义词**。

最后生成 docx：封面按 `references/cover-spec.md`，正文排版调用 `hit-standard-word-type`。

## 交付前自检清单

- [ ] `cnki.py verify` 退出码 0
- [ ] `refs_audit.py check` 退出码 0
- [ ] `refs_audit.py render` 已跑，参考文献由脚本生成
- [ ] `style_lint.py` 无 FAIL
- [ ] 每个二级标题都在回应某个评分点
- [ ] 字数在要求范围内（±10%，不含参考文献）
- [ ] 图表有编号和标题，正文有"如图X所示"的提示
- [ ] 封面字段无空缺
- [ ] 没有"综上所述""首先其次最后"这类套话残留

## 三条红线

1. **绝不编造文献、数据、页码、卷期。** 缺就留空或改写句子绕开。
2. **绝不把没读过的文献写进参考文献。** 摘要都没读过的，不能引。
3. **绝不承诺"包过查重/包过 AI 检测"。** 只能降低特征，检测结果由学校和工具决定。
